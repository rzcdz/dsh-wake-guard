# 唤醒守护

在左侧边栏提供一个入口图标，点击打开面板，用开关控制是否保持电脑可唤醒。

## 使用方式

1. 点击左侧边栏底部的图标打开面板
2. 打开「运行」开关
3. **10 秒后电脑会自动睡眠**（只执行一次）
4. 之后用插座通断电唤醒，本工具会保持系统可用约 10 分钟
5. 用完关闭开关，停止保持，系统恢复正常自动睡眠

**启用插件不会自动运行**，必须手动打开开关。

## 为什么需要它

采用 Modern Standby（S0 低电量待机）的笔记本，从待机被唤醒后如果没有任何活动，
系统会在几秒内重新进入待机，远程客户端来不及重连。

本工具从睡眠唤醒后持续模拟按键（`VK_F15`，几乎所有实体键盘都没有这个键，不会干扰任何程序），
让 Windows 认为用户在场，从而保持唤醒。

## 启动后自动睡眠的原因

打开开关后，工具会先启动保持进程，再等待 10 秒让机器进入睡眠。
这样你可以「打开开关 → 离开」，不必手动合盖或点睡眠。

这个睡眠只执行一次，之后由保持进程维持唤醒。

## 配置

`cordis.patch.yml`：

```yaml
config:
  graceMinutes: 10      # 每次唤醒后保持的分钟数
  suspendDelaySec: 10   # 启动后多久执行睡眠
```

修改后需要停用并重新启用插件。

## 界面说明

- **开关关闭**：无进程运行，系统正常睡眠
- **开关打开**：进程运行，屏幕会周期性亮起（这是保持唤醒的代价）
- 面板会显示运行状态、进程号和最近日志

侧边栏图标右上角有绿点时表示正在运行。

## 重启

面板底部的「重启」按钮。点两次生效：第一次进入确认状态，第二次才真的重启，避免误触。

重启会**结束正在运行的会话**，请先保存工作。重启后页面会自动刷新，回到原来的界面。

两种实现，面板上会显示当前用的是哪种：

- **Electron 重启**：Host 运行在 Electron 主进程里时，直接调用 `app.relaunch()`，和 DSH 更新器用的是同一条路，重启后窗口位置、环境变量都保留。
- **助手进程重启**：Host 不是 Electron 主进程时，派生一个独立的 PowerShell 助手（`scripts/Restart-DSH.ps1`），等 HTTP 响应发完，结束所有 DSH 进程并**确认进程真的退出**，再重新启动可执行文件。先确认退出是关键——Electron 的单实例锁会让新进程把请求交给旧进程然后自己退出，否则重启后会一个进程都不剩。

助手每次动作都写日志：`%LOCALAPPDATA%\dsh-wake-guard-restart.log`。

## 电脑睡眠

面板底部有「电脑睡眠」按钮，点两次生效（第一次进入确认，第二次执行）。

它让电脑进入 **S0 低电量待机（S0ix）**——也就是按任意键就能唤醒的那个状态，**不是休眠 S4**（S4 必须按开机键）。

### 为什么需要临时改设置

只关显示器是不够的。Windows 只有在「显示器关闭」持续到**睡眠空闲超时**之后才会进入 S0ix，而很多机器（包括这台）的交流供电睡眠超时是 `0`（从不）。这种情况下关屏只会得到一块黑着的屏幕，系统仍然全速运行——这正是前一版看起来"没生效"的原因。

所以脚本按这个顺序做：

1. 读当前交流睡眠超时（用 `powercfg /q` 的十六进制值，不依赖界面语言）
2. 临时改为 60 秒（`powercfg /change` 的参数单位是**分钟**，脚本内部做换算）
3. 关闭显示器
4. 等待事件 506（进入 Modern Standby）出现
5. 把原值写回——`0`（从不）会原样恢复为 `0`

`powercfg /change` 对当前用户自己的电源方案不需要管理员权限，这是能这样做的原因。

### 实测记录

```
12:52:57  AC standby timeout before = 0s
12:52:58  AC standby timeout set to 1 min (60s)
12:52:58  506  entering Modern Standby | Reason: SC_MONITORPOWER
12:54:02  507  exiting Modern Standby  | Reason: Input Keyboard
12:54:04  AC standby timeout restored to 0s (set 0 min, now 0s)
```

睡下后按键盘就能唤醒，全程没有事件 42（S4）。

### 为什么不用其他方法

`SetSuspendState` 会显式请求睡眠，但这台机器**没有 S1/S2/S3**，该调用可能落到 S4 休眠，之后必须按开机键。事件日志可以区分：

| 事件 | 含义 |
|---|---|
| 506 `Reason: SC_MONITORPOWER` | 进入 S0ix，按键可唤醒 |
| 42 `Reason: Application API` | 进入 S4 休眠，必须按开机键 |

本脚本不调用 `SetSuspendState`，也不发送虚拟睡眠键（除非显式加 `-IncludeSleepKey`）。

## 日志

`%LOCALAPPDATA%\dsh-wake-guard.log`，面板底部也会显示最近 14 行。

日志里会记录每次的「原值 → 临时值 → 是否进入待机 → 恢复结果」，睡眠没成功时可以直接看出卡在哪一步。

## 限制

- 仅 Windows 生效
- 依赖 DSH 运行；DSH 退出时保持进程一并结束
- 屏幕会周期性亮起，长期开启比较费电，建议按需开关
- 关闭开关后需要几秒让进程退出
